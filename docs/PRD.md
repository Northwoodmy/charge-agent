## 1. 产品概述

### 1.1 定位

「小电拼充电管家」（ChargeAgent）是一款运行在 macOS 菜单栏的充电管理应用：以 Candy 品牌风格可视化小电拼的实时充电数据，并内置双大模型 Agent，让用户用自然语言查询、诊断、控制充电器。

### 1.2 背景

- 小电拼是 CANDYSIGN 出品的 SDC（软件定义充电器），官方提供局域网 HTTP 遥测与云端 MCP 控制能力，但缺乏一个**桌面级的整合体验**。
- 官方云端 MCP 可接入 AI Agent，但依赖 Claude Code 等外部工具，普通用户没有图形化入口。
- 用户（小尉尉）需要：实时数据看板 + 菜单栏常驻 + 可切换的大模型（Kimi / DeepSeek）+ 多设备适配。

### 1.3 价值主张

| 维度 | 价值 |
|---|---|
| 可见 | 500ms 级实时功率、五口状态、160W 共享池调度一目了然 |
| 可说话 | 自然语言查询/控制：「C3 为什么只有 7W」「切到魔拟充」 |
| 可常驻 | 菜单栏应用，开机自启，插拔/离线推送系统通知 |
| 可迁移 | 换一台小电拼只需改设置里的两个地址 |

## 2. 用户与使用场景

### 2.1 目标用户

- 小电拼机主（首要）：日常看管桌面充电；
- 多设备玩家：关注功率分配、协议、线材诊断；
- 极客用户：希望通过 MCP / 自然语言深度控制。

### 2.2 典型场景

1. **余光管理**：菜单栏看「小电拼 58.3W」，无需打开任何窗口；
2. **插拔感知**：插入笔记本 → 系统通知「C1 口接入了新设备」；
3. **诊断**：问 Agent「C3 为什么只有 7W」→ 自动拉 PD 协商与线材信息给出结论；
4. **夜充管理**：「23 点后切慢充」类指令（Agent 执行策略切换）；
5. **多设备迁移**：朋友的小电拼 → 设置页改 IP + MCP 地址即可。

## 3. 产品边界

### 3.1 In Scope

- macOS 菜单栏应用（托盘功率、弹出面板、通知、开机自启）
- 网页版完整看板（与弹窗共用后端）
- 五口实时监控、端口电源开关（三态）
- 温控模式 / 状态屏读取与控制
- 双大模型 Agent（Kimi K2.8 / DeepSeek，可切换）
- 官方云端 MCP 全部 18 个工具（查询 + 控制 + 自动重连）
- 本地历史曲线（JSONL，7 天滚动）
- 设置中心（设备 IP / 兜底代理 / MCP / Key / 模型 / 刷新速率 250ms–5s）
- 桌面悬浮迷你窗（纯读仪表：环形进度 + 五口状态点，位置记忆，自适应高度）
- 品牌定制（小电拼字标、双主题托盘图标、3204 张定宽功率图）

### 3.2 Out of Scope（本期）

- Windows / Linux / Intel mac 版本
- 充电策略的自动编排（如定时任务）——Agent 可手动执行，自动化列入规划
- 多设备同时管理（单设备，切换式）
- 数据同步 / 云端账号体系
- Apple 公证分发（需付费开发者计划）

## 4. 总体架构

```
小电拼 CP02s (192.168.x.x)
   │ ① 本地 HTTP 轮询（500ms 可配，直连优先）
   │ ② 兜底代理（被按应用 VPN 拦截时自动切换）
   ▼
采集器 Collector ──▶ 环形缓冲(500ms级) + 历史存储(JSONL, 7天)
   │
官方云端 MCP (mcp.thecandysign.com, SSE/MQTT) ◀── ③ 控制与富查询
   │                                              （18 工具，掉线自动重连）
   ▼
Express 后端 (127.0.0.1:8932) ── REST API / 静态托管
   │
   ├── 网页版看板 (Vite+React+uPlot, Candy 设计令牌)
   └── 菜单栏弹窗 (#popover 紧凑布局)
              ▲
Electron 外壳：托盘（字标+定宽功率图）/ 通知 / 开机自启

Agent 对话：用户 → Kimi/DeepSeek API → tool-calling → MCP 执行 → 回读确认 → 流式回答
```

### 4.1 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 外壳 | Electron 34 | 菜单栏应用；开发证书签名 |
| 后端 | Node.js（Express） | 打包后以 ELECTRON_RUN_AS_NODE 子进程运行 |
| 前端 | Vite + React 19 + uPlot | 同一构建两个布局（网页 / #popover） |
| 存储 | JSON / JSONL（零依赖） | 兼容 Electron 内置 Node 20（无 node:sqlite） |
| 大模型 | OpenAI 兼容 API | Kimi K2.8（api.kimi.com/coding/v1）/ DeepSeek |

### 4.2 关键工程决策（含踩坑记录）

1. **托盘数字必须图片化**：macOS 状态栏标题用比例字体，定宽字符仍抖动（实测 6 字符宽度差 11px）；预渲染 0.0–160.0W × 明暗主题共 3204 张「字标+数字」合成图，按值换图，宽度恒定 274px。
2. **@2x 规范**：托盘图必须 `name.png + name@2x.png` 成对，否则按 pt 渲染裁边。
3. **端口启停以 `state` 为准**：固件 `active` 字段延迟不可靠，`INACTIVE` 才是权威。
4. **macOS Sequoia 不允许 adhoc 应用经 LaunchServices 启动**：必须有效签名；本机用免费 Apple Development 证书。
5. **Shadowrocket 按应用 VPN 拦截直连**：直连失败挂起 ~1.5s 拖慢采集 → 直连冷却 60s + 代理兜底双通道。
6. **Electron 内置 Node 20 无 `node:sqlite`**：存储层改为 JSON/JSONL 文件。
7. **MCP 单例构造早于配置加载**：连接前强制同步 `config.mcpUrl`，解决「每次启动需重存设置」。
8. **直连被按应用 VPN 拦截会挂起拖慢采集**：直连失败即进入 60s 冷却，期间走代理满速；每分钟探测一次直连恢复。
9. **stroke-dasharray 的 CSS 过渡在 500ms 高频更新下永远卡在起点**（仪表弧线不渲染）：高频更新的 SVG 禁用该过渡。
10. **容器强制 `100vh` 会让「内容高度=窗口高度」自我引用**，自动量高失效：悬浮窗/弹窗改为内容驱动 + 量高贴合。
11. **无边框窗口的移动依赖页面 `-webkit-app-region: drag`**：弹窗标题行、悬浮窗整体声明拖动手柄，控件单独 `no-drag`。
12. **窗口位置存的是 `[x,y]` 数组**：恢复时必须按数组判读（曾误用 `pos.x` 导致悬浮窗位置记忆失效）。
13. **悬浮窗自动恢复须等后端就绪**（否则页面加载失败成透明幽灵窗）：探测 `/api/config` 成功后再建窗。
14. **祖先元素带 transform 会使 fixed 定位改以该祖先为参照**（端口卡 hover 浮起导致弹窗尺寸抖动）：弹层一律 portal 到 body。
15. **Agent 历史的 tool_calls 必须有紧随其后的 tool 响应**（OpenAI 规范），入库顺序为 assistant(工具声明)→tool 结果×N，缺响应的历史自动剥除工具声明。

## 5. 功能需求

> 格式：FR-x.y 描述｜优先级｜验收标准

### 5.1 实时数据看板（网页版）

| 编号 | 需求 | 验收 |
|---|---|---|
| FR-1.1 | 整机总功率大数字 + 总进度条（X/160W） | 与设备 V×A 误差 < 0.2W |
| FR-1.2 | 五口进度条（按各自档位 140/100W 计） | 充电口显示 实际/档位W，空闲口显示「空闲」 |
| FR-1.3 | 五口卡片：V/A/W、协议、本次时长、本次 Wh、三态按钮 | 与官方小程序读数一致 |
| FR-1.4 | 功率曲线：30分钟/1/3/12小时历史 + 实时滚动模式 | 历史 10s 粒度；实时 500ms 内存缓冲 |
| FR-1.5 | 今日统计：累计 Wh、活跃口、整机功率、共享池余量 | 当日 0 点重置 |
| FR-1.6 | 事件流（后端保留） | 插拔/离线触发系统通知 |

### 5.2 菜单栏应用

| 编号 | 需求 | 验收 |
|---|---|---|
| FR-2.1 | 托盘显示小电拼字标 + 定宽功率数字，明暗主题自适应 | 数字变化时其他图标零位移 |
| FR-2.2 | 左键点击弹/收面板（定位图标正下方，带箭头） | 弹出无 blur 竞态闪退 |

## 8. 数据字典

### 8.1 设备原始字段（/metrics.json，每口）

`voltage`(mV) `current`(mA) `power_budget`(W) `session_charge`(µC) `state`(ACTIVE/ATTACHED/INACTIVE) `attached` `fc_protocol` `charging_duration_seconds`

派生：功率 W = V×A/1e6；本次 Wh = Q(µC)/1e6 × V / 3600。

### 8.2 协议码（官方枚举，来自 IonBridge 固件 SW356x config_types.h；界面显示英文规范名）

| 码 | 协议 | 码 | 协议 |
|---|---|---|---|
| 0 | None | 11 | TFCP |
| 1 | QC2.0 | 12 | UFCS |
| 2 | QC3.0 | 13 | PE 1.0 |
| 3 | QC3+ | 14 | PE 2.0 |
| 4 | SFCP | 15 | PD 5V |
| 5 | AFC | 16 | PD Fix HV |
| 6 | FCP | 17 | PD SPR AVS |
| 7 | SCP | 18 | PD PPS |
| 8 | VOOC 1.0 | 19 | PD EPR HV |
| 9 | VOOC 4.0 | 20 | PD AVS |
| 10 | SuperVOOC 2.0 | 255 | Idle |

### 8.2b 设备信息（get_device_info）
SSID、RSSI 信号强度（dBm）、PSN、固件版本——系统抽屉展示网络质量。

### 8.3 主要 REST API

```
GET  /api/status            实时全景（含 viaProxy 标记）
GET  /api/live?seconds=     500ms 环形缓冲
GET  /api/history?port=&minutes=
GET  /api/stats             今日统计
GET  /api/config            采集配置（页面跟随）
GET/POST /api/settings      全部设置（校验+持久化+热生效）
POST /api/mcp/query         只读 MCP 白名单查询
POST /api/control           控制 MCP 白名单执行
POST /api/agent/chat        Agent 对话（tool-calling 循环）
GET  /api/mcp/status        连接状态与工具清单
```

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| Shadowrocket 等按应用 VPN 拦截 | 双通道 + 60s 直连冷却；设置页可配代理 |
| 免费证书到期 | Xcode 一键续期；打包脚本一键重签 |
| ESP32 高频轮询压力 | 速率开放给用户，默认 500ms，250ms 带警示 |
| 官方 MCP 变更 | 工具动态发现（tools/list），系统提示词独立文件 |
| 云端 MCP 单会话 | 健康检查 + 失败自动重建连接 |

## 11. 路线图（规划）

- v1.1：充电自动化（定时策略/功率阈值通知）、钥匙串存 Key、单口功率分配 UI
- v1.2：Intel 版、充电报告（利用 session 数据）、托盘菜单直达常用策略
- v2.0：多设备管理、付费账号公证分发、WidgetKit 通知中心小组件（分钟级快照）
